# 33장 · 개발 도구와 프로젝트 폴더 준비

Part 1 / Ch3 · [전체 실습 목차](../../hands-on/README.md)

## 시작 전 확인

- 장표와 같은 Part·챕터인지 먼저 확인합니다.

- Neo4j 코드는 Browser 입력창에서, bash 명령은 터미널에서 실행합니다. YAML·JSON·Python 파일 링크는 원문을 읽거나 수정할 대상을 뜻합니다.

- 터미널 명령의 기준 위치는 저장소의 `labs/mfg-bom-agent`입니다. 명령이 별도 위치를 지정하면 그 위치를 우선합니다.

- 초기화·적재·색인 명령은 기존 데이터에 영향을 줄 수 있습니다. 전용 실습 환경에서 해당 챕터 안내에 따라 실행하고, 조회만 하려면 다시 초기화하지 않습니다.

- 강사가 저장소를 열면 [Docker와 기본 도구 설치](../../setup/README.md#2-docker와-기본-도구-설치)에서 버전을 확인하고 제조 프로젝트 폴더를 엽니다.

## 1. 도구 설치 확인 · 운영체제 터미널

저장소를 내려받기 전에도 아래 명령을 내 컴퓨터의 터미널에서 실행할 수 있습니다. 도구가 준비됐는지 한꺼번에 확인하거나 설치를 도움받으려면 [Claude Code 또는 Codex용 설치 확인 프롬프트](../../setup/tool-check-prompt.md)를 사용하세요. Git 버전은 Git으로 내려받는 경우에 확인합니다.

```bash
docker --version
docker compose version
uv --version
git --version
```

Compose는 **2.20.0 이상**인지 확인합니다. Python은 다음 장에서 제조 폴더의 환경을 준비한 뒤 확인합니다.

## 2. Docker 실행 확인

Docker 엔진을 켜고 버전을 확인한 터미널에서 실행합니다. 이 명령은 저장소를 내려받기 전에도 사용할 수 있습니다.

```bash
docker run --rm hello-world
```

## 결과 확인과 문제 해결

- 실행 오류가 없는지 먼저 확인하고 장표에서 다룬 입력 조건과 실제 반환값을 대조합니다. 실행 성공만으로 정답이라고 판단하지 않습니다.

- 조회가 비면 파라미터 실행 여부, 입력 식별자, 개정판·질환 등 조건, 데이터 적재 여부, 선택 DB를 차례로 확인합니다.

- 검색은 방식·입력어·필터를 맞추고 본문과 출처를 확인합니다. 서로 다른 검색 점수를 절댓값으로 비교하지 않습니다.

- 모델이나 임베딩 호출 명령은 설정된 API 계정과 사용료가 필요할 수 있습니다. 실제 키는 공유하거나 녹화하지 않습니다.
