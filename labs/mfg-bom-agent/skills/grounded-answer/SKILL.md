# 근거 있는 답변

읽는 사람이 결과를 먼저 이해하고, 필요할 때 계산을 확인할 수 있게 쓴다.

- 답변은 구역으로 나눈다: 첫 문장 답 → 계산 기준(2~3개) → 실행 전에 확인할 사항(1~2개) → 적용 조건(접힘).
  비교표용 한 줄 요약(summary)과 계산 대상(subject) · 계산 기준(basis)도 따로 적는다.
- 첫 문장에서 질문에 답한다. "분석 결과 …"보다 "50대에는 서보 200개가 필요합니다."
- 한 문장에 한 가지 판단만 담는다. 결과 · 산식 · 예외 · 가정을 한 문장에 섞지 않는다.
- 도구 이름 · 산식은 문장에 쓰지 않는다. 화면의 계산 근거가 인용(cited)한 계산 결과의 산식 · 도구 · 입력값을 보여 준다.
- 내부 용어를 업무 용어로 바꾼다: ALTERNATE_OF 없음 → "등록된 대체 부품 없음", ea → "개", pack → "팩".
- 조회 결과와 판단을 구분한다: "대체품이 없습니다"보다 "현재 데이터에 등록된 대체품은 없습니다."
- 확인 요청은 구체적으로 쓴다: "담당자 확인 필요"보다 "재고와 대체 부품 확보 가능성을 확인해야 생산 중단 여부를 판단할 수 있습니다."
- 금액은 무엇의 금액인지 밝힌다: 한 부품만 계산했으면 "로봇 차량 원가"가 아니라 "모터 부품비". 소요 금액 · 구매 금액 · 추가 비용을 섞지 않는다.
- 질문이 변화량을 물으면(얼마나 늘어나나) 증가액을 먼저 쓴다. 어셈블리 경로 설명은 화면의 부품 사용 위치에 맡긴다.
- 숫자는 계산 결과(calculations)에 있는 값만 쓴다. 인용한 숫자는 cited 목록에 label · value · unit 그대로 적는다. 계산하지 않은 항목은 "미계산" · "미확인"으로 쓴다.
- 가정(단종 가정 · 교육용 MOQ · 가상 공급사)과 가격 기준은 가정 · 기준 구역에 숨기지 않고 적는다.
  가격은 "자료 확인일"(자료를 확인한 날)과 "가격 적용일"(원본에 없음)을 구분한다.
- 문서를 근거로 쓰면 문서마다 한국어 한 문장 요약과, 발췌에서 글자 그대로 가져온 관련 문장을 남긴다.
- 설계 승인 · 발주 · 데이터 수정은 하지 않는다.
